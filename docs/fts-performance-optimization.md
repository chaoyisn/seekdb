# 全文索引性能优化与验证

本机基准的参照版本为 `2b6eb18316433fadc1a86fe74a5fa2d1e699685c`。本报告记录实际测量结果，不代表平台正式成绩。

## 零分原因与瓶颈依据

两次平台报告的综合提升率分别约为 -2.05% 和 -12.27%，按题目公式均计零分。同样带有 `git_dirty=1` 的后续提交得到过正分，因此不能用该字段单独解释零分。公开仓库基线与平台结果也不能直接混用。

对实际执行链路采样后，主要修改集中在以下位置：

- 全文索引 DDL 原来强制逐行输出；改为批量输出同一文档的 token，复制该文档不变的源列，保留源行读取、LOB 检查和校验和处理。批次不跨文档，防止引用失效。
- 内部 DDL SQL 原来强制关闭编码排序；仅对全文索引辅助表去掉这一提示，保留类型、排序规则和配置检查，并按展开后的 token 排序场景选择成本路径。修复二进制单 NUL 字符缺少转义字节导致的排序错误。
- 默认分词属性直接使用与原路径一致的默认值，避免 JSON 序列化与重新解析；自定义属性保留原有验证。局部词频表改用无桶锁模式，调用点仍各自独占该表。
- 实际查询热点位于存储层逐文档归并。对最多 8 个维度、自然语言模式且非函数回查的查询，直接选择各倒排列表的最小文档 ID；保留相关度累加顺序、过滤、LIMIT 和结果投影。布尔、函数回查和较大查询继续使用原路径。二进制文档 ID 比较使用等价的字节比较。

## 性能对照

两个版本使用相同 Release 构建方式和独立 seekdb 实例，绑定相同 8 个 CPU，实例配置为 `cpu_count=8`、`memory_limit=4G`、初始数据文件 2G、日志盘 4G。交替运行三轮完整官方参数：`ROWS=20000 BATCH=500 ROUNDS=3000 QUERY_ROUNDS=200 SAMPLES=3 WARMUP=30 SKIP_LOAD=0`。每轮使用新报告文件。下表取三轮各指标的中位数；该统计用于降低波动，不替代平台单次评分。

| 类别 | 指标 | 参照版本 | 优化版本 | 耗时下降 |
| --- | --- | ---: | ---: | ---: |
| 索引构建 | `build_ik_all_sec` | 8.4240 | 7.4310 | 11.79% |
| 索引构建 | `build_ik_content_sec` | 6.3540 | 5.6590 | 10.94% |
| 索引构建 | `build_beng_en_sec` | 3.6430 | 3.0190 | 17.13% |
| 分词 | `tokenize_ik_avg_ms` | 0.1757 | 0.1604 | 8.71% |

## 正确性验证

- Release seekdb 目标编译成功；构建所用修改文件与提交源码逐文件核对。
- 三轮完整测试的命中数均为 8001、11000、7332、20；每轮另核对 35,678 条 MATCH ID 和六位小数相关度记录，均与参照版本一致。
- 38 组额外查询覆盖 1–12 个查询词、空/不存在/重复查询词、OFFSET、布尔查询、函数回查与分区切换，共 29,309 条未舍入的浮点相关度记录，与前一已验证版本逐位相同。
- 720 组分词结果与参照版本一致，覆盖 Unicode、NULL/空文本、不同解析器、自定义属性及错误输入；12 路并发首次 IK 分词通过。
- 5000 个不同词的 LONGTEXT 文档、空文档、NULL、分区表和更新后的旧词移除检查通过。
- 1017 条随机和边界字符串在 binary、utf8mb4_bin、utf8mb4_general_ci 下，编码排序与普通排序的升降序结果一致。
- 已扩展标准 `tokenize_regression.test`，覆盖复合主键、跨批次词项、8/9 词边界、布尔/函数回查和二进制 NUL。标准回归 SQL 的实际结果与预期文件逐字一致；未执行全库测试套件。

## 评分与复现限制

满分要求综合耗时下降至少 50%。当前本机结果尚不足以支持满分结论，也不能据此预测平台分数。WSL 的客户端和 I/O 开销与平台不同，正式成绩仍应使用平台固定基线。性能基准脚本、测试数据、SQL、计时方式、评分脚本和固定基线均未修改。

本机原始报告与差分输出位于 `D:/OceanBase/fts-*-final*-official-report.txt`、`fts-final-summary.json` 和查询矩阵输出文件。报告中的 git_head 来自临时 Linux 验证树；二进制对应的源码另外逐文件核对，不能用该元数据推断提交版本。
