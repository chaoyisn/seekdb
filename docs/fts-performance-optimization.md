# 全文索引优化与验证

本轮参照版本为 `3a6cdf2bea1feadbe4c5ab6b3c4b19dac77eeccc`，该版本最新平台正式成绩为 **17.1592 / 50**。以下数据来自同机对照，新的平台正式成绩尚未获得。

## 零分原因

此前两次平台综合提升率约为 -2.05% 和 -12.27%，按公式均计零分。后续同样带有 `git_dirty=1` 的报告获得正分，该字段不能单独解释零分。公开仓库基线、本机参照版与平台固定基线必须分别使用。

## 瓶颈与修改

- 查询计划原来始终计算相关性。对无需回表、无附加过滤或函数回查的覆盖 MATCH 扫描，复用表达式依赖分析，仅在各处只观察匹配真值时省去 BM25 统计和计算。输出分值、数值阈值及排序等依赖保留计分；零阈值参数约束加入计划缓存约束。布尔模式、ES、boost 查询保留原路径。
- 补齐无分值 DAAT/TAAT 的初始化、复用、文档缓存及匹配标记，避免读取缺省的统计对象或跳过位图。标记的正值只表示匹配存在，不替代可观察的数值分值。大词数 TAAT 继续利用文档数估计选择哈希分区。
- 外层唯一 COUNT(*)、内层单表普通 LIMIT 的严格安全形状中，行数为 `min(limit, max(input_rows-offset, 0))`。识别此形状后复用投影裁剪工具保留常量输出，执行原有全文表达式校验，再移除不可观察的隐式排序及源列回表，保留 LIMIT、OFFSET 与检索处理。涉及可观察值、DISTINCT、窗口、FETCH、FOUND_ROWS 或副作用等形状不适用。
- BENG 将规范化输出直接分配在调用方 arena，省去重复分配复制；词频表用 set_or_update 合并两次哈希查找，保留初始词频及最后词形；IK 固定四个处理器的原有调用顺序并直接调用，每个字符仍经过四个处理器。

索引构建沿用参照版已验证的批量输出及排序实现。官方数据、SQL、计时、评分、固定基线和 CI 配置均未修改。
