# 全文索引优化与验证

参照提交为 `621a4871e61191344d86645c18972015b7886d80`，用户提供的平台正式成绩为 **23.2918 / 50**，综合提升率 23.2918%。本轮提交的新平台成绩尚未获得；以下是相对此提交的本机增量。

## 原因与最终修改

此前零分报告的综合提升率为 -2.05% 和 -12.27%，按评分公式均为零。后续同样带 `git_dirty=1` 的报告获得正分，该字段不能单独解释零分。公开仓库固定基线、本机参照与平台基线分别使用，未修改官方基准、SQL、数据、计时、评分、基线或工作流。

- 构建剖析显示排序、溢写与行搬运占主要 CPU。FTS 的倒排和 doc-word 辅助表可独立构建，但 mini 模式 DDL 构建队列原来只有一个线程。现在按已配置的 CPU 数允许最多两个工作线程，单 CPU 仍为一个；正常模式保留原有 16。SQL 工作区、租户内存及执行并行度限制继续生效。此调整也影响 mini 模式的并发普通 DDL，已补做混合并发验证。
- 全文 DDL 的扫描行数描述源文档，常被估计为极小值，不能据此把展开后的 token 行批大小收缩到 16。在 FTS 辅助表在线构建中禁用这一收缩条件，其余表达式、LOB、配置、hint 和副作用检查保留。
- 小词数 DAAT 在每次批调用中缓存迭代器和固定数组地址，比较器直接读取固定 ID 指针数组，已缓存的 posting 行直接返回 ID 和原分值。数组在初始化后保持地址稳定，reuse 不重分配；评分累加顺序、过滤、OFFSET、LIMIT 与其他归并路径不变。
- UTF-8 小写转换对 ASCII 使用原 Unicode 映射表直接输出，避免 UTF-8 解码和重编码。映射超出 ASCII、非 ASCII、非法序列或输出空间不足仍走原路径，输出分配和所有权不变。没有缓存 TOKENIZE 结果或改变分词规则。整体分词实测见下表，不单独宣称该修改带来稳定收益。

逐行到批读取的 SSTable 写入实验在六组显式分值检查中产生差异，最终提交已撤回该实验。最终全部分值差分与参照版一致。

- Release 编译通过，44 个内核源文件与原生编译副本逐文件相同。最终二进制 SHA256：`06437d8ab93876280f2996d74d49bfe823cd19734c91bb6fcbb36d47f07949fb`。
- 与参照版按相同数据及测试顺序比较 11 份语义产物，全部相同，包括 35,678 条 ID/六位小数分值、38 组查询的 29,309 条逐位浮点分值、36 组查询的 65,763 条完整 ID。

- 2GB 实例冷启动后 12 个并发 IK 会话结果正确；同时提交三个不同解析器全文索引与一个普通索引构建，均覆盖分区，随后完整 ID 与更新结果通过。实际 DDL 工作线程数为 2。

## 已知限制与评分

Top-K 48 组 LIMIT/OFFSET 中，参照版已有 38 组显式相关性排序带次排序键的同分 ID 选取问题。最终版输出与参照版完全相同，隐式 Top-K 未出现该矩阵失败；本轮没有修复这一既有问题。查询命中数和耗时均不能替代完整正确性验证。

平台满分要求相对其固定基线综合耗时下降至少 50%。当前正式成绩仍以 23.2918 / 50 为已知值，新提交需平台重新评测。WSL 的客户端和 I/O 与平台不同，本机增量不用于承诺正式分数。
